# Skill-Desk 0.4.0

## Review recommendations before installing

Recommendations now have a clear **Review & install** action. Read the instructions, check the destination agent, and choose whether to install, save, or dismiss each suggestion. Completed and cancelled jobs retain their actual outcomes after restart without replaying agent requests. Local diagnostic reports use fixed failure codes and exclude conversation text.

## Maintain your skill library

Edit draft instructions and supporting files, compare changes, save drafts and templates, and restore earlier revisions. Review upstream updates with immutable source references and explicit conflict choices. Search full instructions, organize skills with local notes and collections, and compare copies across agents.

Back up selected skills, settings and saved drafts. Review each item before restoring it, with explicit choices for existing destinations and recovery records for interrupted changes.

## Choose agents and review history

Use personal and project destinations for Codex, Claude Code, OpenCode and Cursor. Select models where supported and run an explicit connection test. History previews show coverage and allow excerpt edits, exclusions and a deeper scan before a recommendation request.

Automatic history recommendations remain limited to Codex and Claude Code. OpenCode history recommendations and Windows library relocation remain unavailable. Cursor live-account compatibility has not been established by the synthetic checks.

## Security and reliability

Update Pillow, PyInstaller and compatible Tauri dependencies. Tighten web asset containment, bound Nearby address parsing, validate saved revision and supporting-file paths before reading or writing, preserve portable paths on Windows, and preserve malformed job records without startup failure or replay.

The Linux GTK stack uses a checksum-verified copy of glib 0.18.5 with the upstream iterator safety fix backported. Linux validation uses CI, including optimized iterator regressions and isolated AppImage interactions; hands-on Linux testing is deferred. Updater packages use the existing signing configuration; Windows publisher signing and macOS notarization are not configured.
